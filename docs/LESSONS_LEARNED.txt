LESSON 1: WHITE RECTANGLE BORDER ON REGION SELECTION (Leaflet Popups)
================================================================================
Date: 2026-01-26
Issue: White rectangular border appears around popups when selecting a region

ROOT CAUSE:
- Leaflet's default SVG rendering can draw bounding box rectangles
- Browser focus outlines on popup elements
- Inherited borders from popup containers

FIX (add to CSS):
--------------------------------------------------------------------------------
/* Hide any bounding box rectangles that Leaflet might draw */
.leaflet-overlay-pane svg rect,
.leaflet-overlay-pane path[stroke="white"][fill="none"],
.leaflet-overlay-pane path[stroke="#ffffff"][fill="none"],
.leaflet-overlay-pane path[stroke="#fff"][fill="none"] {
    display: none !important;
}

/* Remove ALL outlines from popup elements */
.leaflet-popup, .leaflet-popup *, .leaflet-popup-content-wrapper,
.leaflet-popup-tip-container, .leaflet-popup-pane, .leaflet-popup-pane * {
    outline: none !important;
}

/* Fix focus rings on interactive elements */
.leaflet-container *:focus {
    outline: none !important;
}

/* Ensure popup has proper shadow, no white borders */
.leaflet-popup-content-wrapper {
    box-shadow: 0 4px 20px rgba(0, 0, 0, 0.5) !important;
    border: none !important;
}
--------------------------------------------------------------------------------

File: frontend/styles_v3.1.css (around line 1050)

LESSON 2: AUTOMATIC LAYER DISCOVERY FOR GEO-AI ANALYTICS
================================================================================
Date: 2026-01-26
Issue: Adding new layers required manual updates to iSEE Analytics function

PROBLEM:
- Each new layer type (land cover, vegetation, etc.) required manually adding
  the layer name to the iSEE Analytics function
- Not scalable for 20+ layers
- Easy to forget and causes analytics to miss layers

SOLUTION - AUTOMATIC LAYER DISCOVERY:
--------------------------------------------------------------------------------
All layers are registered with regionLockState when loaded:

    regionLockState.addLayer(layerName, leafletLayer, layerType)

Layer types supported:
- 'nightlight'     - Nightlight/radiance data
- 'roads'          - Road infrastructure
- 'population'     - Population distribution
- 'landcover'      - Land cover classification
- 'vegetation'     - Vegetation indices (NDVI, EVI, etc.)
- 'socioeconomic'  - MPI, poverty, economic data
- 'infrastructure' - Other infrastructure
- 'other'          - Any other type

iSEE Analytics automatically discovers ALL layers from regionLockState:

    const layerRefs = {
        // Auto-discovered layers
        dynamicLayers: dynamicLayers,           // All layers by safe key
        layersByType: layersByType,             // Layers grouped by type
        loadedLayersList: regionLockState.loadedLayers,  // Raw list

        // Legacy support still works
        ...legacyRefs
    };
--------------------------------------------------------------------------------

HOW TO ADD A NEW LAYER TYPE:
1. Create the layer loading code (drag-drop handler, etc.)
2. Register with regionLockState:

       regionLockState.addLayer('Land Cover 2024 - Bakool', landCoverLayer, 'landcover');

3. That's it! iSEE Analytics will automatically include it.

HOW TO ACCESS LAYERS IN iSEE ANALYTICS MODULE (isee_analytics.js):
--------------------------------------------------------------------------------
// Access all layers of a specific type:
const nightlightLayers = layerRefs.layersByType.nightlight;
const roadsLayers = layerRefs.layersByType.roads;
const landcoverLayers = layerRefs.layersByType.landcover;

// Access a specific layer by name:
const layer = layerRefs.dynamicLayers['land_cover_2024___bakool'];

// Iterate all loaded layers:
layerRefs.loadedLayersList.forEach(layer => {
    console.log(layer.name, layer.type, layer.layer);
});
--------------------------------------------------------------------------------

LESSON 3: SCOPE ISSUES WITH LAYER REFERENCES
================================================================================
Date: 2026-01-26
Issue: Functions defined outside setTimeout couldn't access layer variables

PROBLEM:
- triggerISEEAnalytics was defined at outer scope
- Layer variables (detailedNLBakool2022, activeRoadsOSMLayer, etc.) are inside setTimeout
- Function couldn't access layer references, passed empty {}

SOLUTION - DEFERRED IMPLEMENTATION PATTERN:
--------------------------------------------------------------------------------
// At outer scope - create placeholder
var triggerISEEAnalyticsImpl = null;

function triggerISEEAnalytics(regionName, regionLayer) {
    if (triggerISEEAnalyticsImpl) {
        triggerISEEAnalyticsImpl(regionName, regionLayer);
    } else {
        alert('Please wait for dashboard to fully load');
    }
}

// Inside setTimeout where layer variables exist
setTimeout(() => {
    // Now we have access to all layer variables
    triggerISEEAnalyticsImpl = function(regionName, regionLayer) {
        // Full implementation with access to:
        // - detailedNLBakool2022, detailedNLBakool2023
        // - activeRoadsOSMLayer, clippedRoadsLayer
        // - mpiLayer, populationLayer
        // - etc.
    };
}, 100);
--------------------------------------------------------------------------------

USE THIS PATTERN WHEN:
- You need a function accessible globally (e.g., from context menus)
- But the function needs access to variables defined in setTimeout/async blocks

LESSON 5: DATE FORMAT CONSISTENCY (HDX API / File System)
================================================================================
Date: 2026-01-26
Issue: Date format mismatch between API responses and folder names

PROBLEM:
- HDX API returns dates as: 2024-07-23 (ISO format with dashes)
- Folder names use: 2024_07_23 (underscores)
- Comparison failed, versions showed as "not installed"

SOLUTION:
--------------------------------------------------------------------------------
In check_osm_version.py:

def get_date_part(date_str):
    """Extract YYYY_MM_DD from ISO datetime (underscore format for folder names)"""
    if 'T' in date_str:
        return date_str.split('T')[0].replace('-', '_')
    return date_str.replace('-', '_')
--------------------------------------------------------------------------------

ALWAYS convert dates to underscore format when comparing with folder names.

LESSON 6: GIT LFS AND GITHUB PAGES INCOMPATIBILITY
================================================================================
Date: 2026-01-24
Issue: Large road files not loading when hosted on GitHub Pages

PROBLEM:
- Used Git LFS for large road files (>50 MB)
- GitHub Pages doesn't serve Git LFS files properly
- Returns LFS pointer text instead of actual file content
- Breaks drag-and-drop functionality completely

SOLUTION:
--------------------------------------------------------------------------------
1. Don't use Git LFS for files needed by GitHub Pages
2. Optimize files to stay under GitHub's 100 MB limit instead
3. If files are too large, use external hosting or a backend server

To remove Git LFS tracking:
    git lfs untrack "*.geojson"
    git rm --cached path/to/file.geojson
    git add path/to/file.geojson
    git commit -m "Remove LFS tracking"
--------------------------------------------------------------------------------

ALTERNATIVE: Optimize GeoJSON files (see Lesson 7)

LESSON 7: GEOJSON FILE SIZE OPTIMIZATION
================================================================================
Date: 2026-01-24
Issue: Road data files too large for fast loading (1.27 GB total)

PROBLEM:
- Original road files had 10+ decimal precision in coordinates
- Unnecessary whitespace in JSON
- Bay region alone was 139 MB

SOLUTION - COORDINATE PRECISION REDUCTION:
--------------------------------------------------------------------------------
# Python optimization script pattern
import json

def optimize_geojson(input_path, output_path, precision=5):
    with open(input_path) as f:
        data = json.load(f)

    def round_coords(coords, precision):
        if isinstance(coords[0], list):
            return [round_coords(c, precision) for c in coords]
        return [round(coords[0], precision), round(coords[1], precision)]

    for feature in data['features']:
        geom = feature['geometry']
        geom['coordinates'] = round_coords(geom['coordinates'], precision)

    with open(output_path, 'w') as f:
        json.dump(data, f, separators=(',', ':'))  # Minified
--------------------------------------------------------------------------------

RESULTS:
- 5-6 decimal precision = ~1-11cm accuracy (sufficient for roads)
- Total size: 849 MB -> 219 MB (74% reduction)
- Bay region: 139 MB -> 35 MB (75% reduction)
- Load time: 4x faster

Files: tools/optimize_geojson.py, tools/optimize_roads_js.py

LESSON 8: DYNAMIC SCRIPT LOADING - GLOBAL SCOPE ISSUES
================================================================================
Date: 2026-01-24
Issue: Variables defined in dynamically loaded scripts not accessible

PROBLEM:
- Used eval() to execute dynamically loaded JavaScript
- Variables defined with var/let/const stayed in eval() scope
- Main script couldn't access the loaded data

SOLUTION - USE INDIRECT EVAL FOR GLOBAL SCOPE:
--------------------------------------------------------------------------------
// WRONG - variables stay in local scope
eval(scriptContent);

// CORRECT - variables go to global scope
(1, eval)(scriptContent);

// Or use Function constructor
const loadScript = new Function(scriptContent);
loadScript();

// Or assign to window explicitly in the loaded script
window.myData = { ... };
--------------------------------------------------------------------------------

USE WHEN: Loading GeoJSON data files dynamically via fetch()

Files affected: All drag-drop handlers that load .js data files

LESSON 9: BROWSER CACHE ISSUES DURING DEVELOPMENT
================================================================================
Date: 2026-01-24
Issue: Code changes not reflecting in browser despite deployment

PROBLEM:
- Browser aggressively caches JavaScript and CSS files
- Users see old version of dashboard
- Confusing during development and testing

SOLUTION - MULTI-LAYER CACHE BUSTING:
--------------------------------------------------------------------------------
1. Add version parameter to script/CSS URLs:
   <script src="script.js?v=3.1&t=1706234567"></script>

2. Add cache-control meta tags:
   <meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate">
   <meta http-equiv="Pragma" content="no-cache">
   <meta http-equiv="Expires" content="0">

3. Use build timestamp in JavaScript:
   const buildTime = Date.now();
   document.write('<script src="script.js?v=' + version + '&b=' + buildTime + '"><\/script>');

4. Add "Clear Cache & Reload" button for users:
   location.reload(true);  // Force reload from server
--------------------------------------------------------------------------------

LESSON 10: UNICODE ENCODING IN PYTHON ON WINDOWS
================================================================================
Date: 2026-01-23
Issue: Python scripts crashing with UnicodeEncodeError on Windows

PROBLEM:
- Python print() uses system encoding on Windows (cp1252)
- Emojis and special characters in output cause crashes
- Server logs fail when processing international text

SOLUTION:
--------------------------------------------------------------------------------
# At the top of Python scripts, force UTF-8 output:
import sys
import io
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace')
sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding='utf-8', errors='replace')

# Or set environment variable before running:
set PYTHONIOENCODING=utf-8
--------------------------------------------------------------------------------

LESSON 14: ROAD TYPE STANDARDIZATION (BRIDGING TABLE)
================================================================================
Date: 2026-01-24
Issue: Different road datasets use different classification systems

PROBLEM:
- OSM uses: motorway, trunk, primary, secondary, tertiary, residential, track...
- HDX 2021 uses: Highway, Primary, Secondary, Tertiary, Local...
- HDX 2024 uses: different variations
- No consistent styling or analysis

SOLUTION - BRIDGING TABLE:
--------------------------------------------------------------------------------
const ROAD_BRIDGING_TABLE = {
    // Standard Class -> [aliases from different sources]
    'Highway':     ['motorway', 'trunk', 'Highway', 'highway'],
    'Primary':     ['primary', 'primary_link', 'Primary', 'primary road'],
    'Secondary':   ['secondary', 'secondary_link', 'Secondary'],
    'Tertiary':    ['tertiary', 'tertiary_link', 'Tertiary'],
    'Residential': ['residential', 'living_street', 'Residential', 'Local'],
    'Track':       ['track', 'path', 'Track', 'trail'],
    'Unclassified':['unclassified', 'road', 'Unknown', '']
};

function standardizeRoadType(rawType) {
    for (const [standard, aliases] of Object.entries(ROAD_BRIDGING_TABLE)) {
        if (aliases.includes(rawType)) return standard;
    }
    return 'Other';
}
--------------------------------------------------------------------------------

LESSON 16: PORT CONFLICT RESOLUTION
================================================================================
Date: 2026-01-24
Issue: "Port already in use" errors when restarting dashboard

PROBLEM:
- Previous Python processes not properly terminated
- Ports 8000 and 5000 remain occupied
- New server instances fail to start

SOLUTION:
--------------------------------------------------------------------------------
REM In batch script - aggressive port clearing

REM Kill by port
for /f "tokens=5" %%a in ('netstat -aon ^| findstr ":8000.*LISTENING"') do (
    taskkill /F /PID %%a 2>nul
)

REM Kill Python processes
taskkill /F /IM python.exe /FI "WINDOWTITLE eq *http.server*" 2>nul

REM Wait for ports to be released
timeout /t 2 /nobreak >nul

REM Verify port is free before starting
netstat -an | findstr ":8000.*LISTENING" >nul
if %errorlevel%==0 (
    echo ERROR: Port 8000 still in use
    exit /b 1
)
--------------------------------------------------------------------------------

Files: launcher/start_dashboard.bat

LESSON 18: OSM ROADS FORMAT DETECTION
================================================================================
Date: 2026-01-23
Issue: iSEE Analytics failing because OSM data has different structure

PROBLEM:
- Legacy roads use: { roads: { features: [...] } }
- OSM roads use: { metadata: {...}, features: [...] }
- Analytics assumed legacy format, crashed on OSM data

SOLUTION:
--------------------------------------------------------------------------------
function detectRoadsFormat(data) {
    // Check for OSM format (has metadata.data_source)
    if (data.metadata && data.metadata.data_source === 'OpenStreetMap') {
        return 'osm';
    }
    // Check for legacy format (has roads wrapper)
    if (data.roads && data.roads.features) {
        return 'legacy';
    }
    // Direct GeoJSON
    if (data.features) {
        return 'geojson';
    }
    return 'unknown';
}

// Use appropriate extraction
const features = format === 'osm' ? data.features :
                 format === 'legacy' ? data.roads.features :
                 data.features;
--------------------------------------------------------------------------------

LESSON 19: DROP ZONE VALIDATION - ONLY LOCKED REGION
================================================================================
Date: 2026-01-26
Issue: Users could drop layers anywhere on the map, causing confusion

PROBLEM:
- Drag-drop allowed dropping anywhere on the map
- System would auto-apply to locked region regardless of drop location
- Users confused about where to drop layers
- No clear feedback when dropping outside valid zone

SOLUTION - POINT-IN-REGION VALIDATION:
--------------------------------------------------------------------------------
// Helper function to check if point is in locked region
function isPointInLockedRegion(latlng) {
    if (!regionLockState.isLocked || !regionLockState.lockedRegionLayer) {
        return false;
    }
    const bounds = regionLockState.lockedRegionLayer.getBounds();
    return bounds.contains(latlng);
}

// Show warning when dropping outside locked region
function showDropOutsideRegionWarning(layerName, latlng) {
    L.popup({ className: 'drop-invalid-popup' })
        .setLatLng(latlng)
        .setContent(`🚫 Drop not allowed here - Drop on ${regionLockState.lockedRegion}`)
        .openOn(map);
}

// In each drop handler, add validation:
if (!isPointInLockedRegion(latlng)) {
    showDropOutsideRegionWarning('Layer Name', latlng);
    return;
}
--------------------------------------------------------------------------------

VISUAL FEEDBACK:
- Green highlight + "✓ Drop to load..." when over locked region
- Red cursor + "🚫 Drop only on [Region]" when outside
- Warning popup if dropped in wrong location

function resetISEEAnalytics() {

    iseeAnalyticsActive = false;

LESSON 22: SCALABLE DRAG-DROP ARCHITECTURE (FUTURE)
================================================================================
Date: 2026-01-26
Issue: Each layer has duplicate drag-drop handler code

PROBLEM:
- 6+ layers each with separate dragstart, dragover, drop handlers
- Same validation logic repeated in each
- Adding 100 layers = 100x code duplication
- Maintenance nightmare

SOLUTION - CENTRALIZED DRAG-DROP MANAGER (TO IMPLEMENT):
--------------------------------------------------------------------------------
const DragDropManager = (function() {
    const registeredLayers = {};

    function register(config) {
        // config = { id, label, type, onDrop, ... }
        registeredLayers[config.id] = config;
        setupDragStart(config);
    }

    // Single global dragover handler
    mapContainer.addEventListener('dragover', function(e) {
        const draggedId = getCurrentDraggedId();
        if (!draggedId || !registeredLayers[draggedId]) return;

        e.preventDefault();
        const isValid = isPointInLockedRegion(getLatlngFromEvent(e));
        updateVisualFeedback(isValid, registeredLayers[draggedId]);
    });

    // Single global drop handler
    mapContainer.addEventListener('drop', function(e) {
        const draggedId = getCurrentDraggedId();
        if (!isPointInLockedRegion(latlng)) {
            showDropOutsideRegionWarning(registeredLayers[draggedId].name, latlng);
            return;
        }
        registeredLayers[draggedId].onDrop(latlng);
    });

    return { register };
})();

// Usage - one line per layer
DragDropManager.register({ id: 'roadsOSM', name: 'Roads OSM 2023', onDrop: loadRoads });
--------------------------------------------------------------------------------

Date: 2026-01-27
Issue: Cannot programmatically detect when user completes external OS actions

PROBLEM:
- Protocol installation wizard downloads a .reg file
- User must complete 6 steps in Windows (double-click, Run, Yes, Yes, OK)
- JavaScript cannot detect Windows dialogs or registry changes
- Users could click "Verify" before actually completing installation
- Led to failed verifications and user confusion

ROOT CAUSE:
- Browser sandboxing prevents access to OS-level events
- No API to detect Windows UAC dialogs, registry editor, or file execution
- Relying on user to click "Verify" at the right time is unreliable

SOLUTION - CONFIRMATION CHECKBOX PATTERN:
--------------------------------------------------------------------------------
Instead of:
1. Download button (enabled)
2. Verify button (enabled immediately after download)
   → User clicks too early, verification fails

Use:
1. Download button (blinking green - active)
2. After download: Show confirmation checkbox
3. Checkbox: "I completed all 6 steps and clicked OK on the success message"
4. Verify button stays DISABLED (yellow) until checkbox is checked
5. When checkbox checked: Verify button becomes ENABLED (blinking green)
--------------------------------------------------------------------------------

IMPLEMENTATION:
--------------------------------------------------------------------------------

function onConfirmCheckboxChange() {
    const checkbox = document.getElementById('confirmOkClicked');
    const verifyBtn = document.getElementById('verifyBtn');

    if (checkbox.checked) {
        // User confirmed - enable with visual emphasis
        verifyBtn.classList.remove('disabled', 'waiting-yellow');

        verifyBtn.classList.add('disabled', 'waiting-yellow');
        updateStatus('loading', 'Waiting for you to complete steps...');
    }
}

--------------------------------------------------------------------------------
// modules/l1-clip.js - Single source of truth for L1 clipping

var L1Clip = (function() {
    let regionIndex = {};  // { regionName: GeoJSON feature }

    // Initialize once with Somalia L1 boundaries
    async function init() {
        const response = await fetch('layers/boundaries/adm1/somalia_adm1_boundaries.geojson');
        const data = await response.json();

        for (const feature of data.features) {
            regionIndex[feature.properties.name] = feature;
        }
    }

    // Check if point is in region (ray casting algorithm)
    function isPointInRegion(regionName, point) {
        const region = regionIndex[regionName];
        return pointInGeometry([point.lng, point.lat], region.geometry);
    }

    // Filter GeoJSON by region
    function filterByRegion(regionName, geojson) {
        const region = regionIndex[regionName];
        return {
            type: 'FeatureCollection',
            features: geojson.features.filter(f =>
                featureIntersectsRegion(f, region.geometry)
            ),
            metadata: {
                region: regionName,
                originalCount: geojson.features.length,
                filteredCount: filteredFeatures.length
            }
        };
    }

    return { init, isPointInRegion, filterByRegion, ... };
})();

// Usage in any layer - ONE LINE:
const bakoolRoads = L1Clip.filterByRegion('Bakool', roadsData);
--------------------------------------------------------------------------------

BENEFITS:
1. **Consistency**: Same algorithm used everywhere
2. **Maintainability**: Fix bug once, fixed everywhere
3. **Scalability**: 100 layers = 100 one-liners, not 100 × 100 lines
4. **Testability**: Single module to test
5. **Performance**: Can optimize one place for all layers

SUPPORTED GEOMETRY TYPES:
- Point: checks if inside region
- MultiPoint: checks if ANY point inside
- LineString: checks endpoints + midpoints
- MultiLineString: checks ANY line
- Polygon: checks centroid + vertices
- MultiPolygon: checks ANY polygon

API REFERENCE:

import rasterio
import geopandas as gpd
from shapely.geometry import box
import numpy as np
import os

def raster_to_vector(tif_path, output_path, nodata_value=0):
    """Convert GeoTIFF to GeoJSON grid polygons"""
    with rasterio.open(tif_path) as src:
        data = src.read(1)
        transform = src.transform
        crs = src.crs

    polygons = []
    values = []
    rows, cols = data.shape

    for row in range(rows):
        for col in range(cols):
            val = data[row, col]
            if val > nodata_value:
                x1, y1 = rasterio.transform.xy(transform, row, col, offset='ul')
                x2, y2 = rasterio.transform.xy(transform, row+1, col+1, offset='ul')
                polygons.append(box(min(x1,x2), min(y1,y2), max(x1,x2), max(y1,y2)))
                values.append(float(val))

    gdf = gpd.GeoDataFrame({'population': values, 'geometry': polygons}, crs=crs)
    gdf.to_file(output_path, driver='GeoJSON')
    return len(gdf)

def clip_by_regions(input_geojson, boundaries_geojson, output_dir):
    """Clip GeoJSON by each L1 region"""
    data = gpd.read_file(input_geojson)
    regions = gpd.read_file(boundaries_geojson)

    for _, region in regions.iterrows():
        name = region['name'].replace(' ', '_')
        clipped = gpd.clip(data, region.geometry)
        if len(clipped) > 0:
            output_path = os.path.join(output_dir, f'{name}_population.geojson')
            clipped.to_file(output_path, driver='GeoJSON')
            print(f'{name}: {len(clipped)} cells')
--------------------------------------------------------------------------------

PERFORMANCE NOTES:
- 1km resolution = ~600,000 cells for Somalia (sparse, most are 0)
- After filtering nodata: typically 10,000-50,000 valid cells
- Processing time: ~30-60 seconds per year
- Output size: ~5-20 MB per region (depends on population density)

TROUBLESHOOTING:
- "ModuleNotFoundError: No module named 'rasterio'"
  → Run: python -m pip install rasterio

- "PROJ: proj_create_from_database: Cannot find proj.db"
  → Set PROJ_LIB environment variable or reinstall pyproj

- Large file processing slow
  → Use chunked reading with rasterio.open().read(window=...)

LESSON 26: RASTER-TO-VECTOR OPTIMIZATION - FILTER NODATA/ZERO CELLS
================================================================================
Date: 2026-01-28
Issue: Converting full raster to vector creates massive files with useless data

PROBLEM:
- WorldPop 1km raster for Somalia: 2,050,389 total cells
- Only 230,273 cells (11.2%) have actual population data
- NoData cells: 1,819,795 (88.8%) - ocean, outside country
- Zero cells: 321 (0.0%) - uninhabited land
- Converting ALL cells would create 2M+ polygon GeoJSON (~500+ MB)
- Dashboard would be extremely slow loading/rendering

ROOT CAUSE:
- Raster format uses fixed grid covering bounding box of country
- Grid includes ocean (NoData) and uninhabited areas (zero population)
- Naive conversion creates polygons for every cell regardless of value

SOLUTION - FILTER DURING CONVERSION:
--------------------------------------------------------------------------------
# In raster_to_vector(), ONLY convert cells with population > threshold

# 1. Identify nodata value from raster metadata
with rasterio.open(tif_path) as src:
    data = src.read(1)
    nodata = src.nodata  # e.g., -99999.0

# 2. Create mask for valid cells ONLY
nodata_mask = (data == nodata) | np.isnan(data)
valid_mask = (~nodata_mask) & (data > MIN_POPULATION)

# 3. Get indices of valid cells only
valid_rows, valid_cols = np.where(valid_mask)

# 4. Only create polygons for valid cells
for row, col in zip(valid_rows, valid_cols):
    # Create polygon...
    polygons.append(...)
    populations.append(data[row, col])
--------------------------------------------------------------------------------

RESULTS:
- Before optimization: 2,050,389 polygons
- After optimization:    230,273 polygons
- Reduction: 88.8%
- File size: ~500 MB → ~50 MB (estimated)

CONFIGURATION OPTIONS:
--------------------------------------------------------------------------------
# In process_worldpop.py:

MIN_POPULATION = 0.0   # Include any cell with population > 0
# MIN_POPULATION = 1.0   # Skip cells with fractional population < 1
# MIN_POPULATION = 10.0  # Only include cells with 10+ people (aggressive)
--------------------------------------------------------------------------------

APPLY THIS PATTERN TO ALL RASTER-TO-VECTOR CONVERSIONS:
1. Identify nodata value from raster metadata
2. Create boolean mask: valid = (not nodata) AND (value > threshold)
3. Use np.where(valid_mask) to get indices of valid cells only
4. Only iterate over valid cells

DATA TYPE NOTE:
- Downloaded data is Total Population (Constrained) - adjusted to UN estimates
- File naming: som_pop_YYYY_CN_1km_R2025A_UA_v1.tif
  - CN = Constrained
  - UA = Urban/Rural Adjusted
  - v1 = Version 1
- NOT age/sex disaggregated (that would be separate dataset)

2. jsDelivr CDN - serves from GitHub, 50 MB limit

5. Self-hosted backend - full control

// modules/data-loader.js
const DataLoader = (function() {
    const cache = new Map();

    async function loadGeoJSON(url, cacheKey) {
        if (cache.has(cacheKey)) return cache.get(cacheKey);

        const response = await fetch(url);
        const data = await response.json();
        cache.set(cacheKey, data);
        return data;
    }

    async function loadRoads(regionName, folder) {
        const cacheKey = `roads_${folder}_${regionName}`;
        const url = `../data_warehouse/roads/${folder}/${regionName}_roads.geojson`;
        return loadGeoJSON(url, cacheKey);
    }

    function clearCache(cacheKey) {
        if (cacheKey) cache.delete(cacheKey);
        else cache.clear();
    }

    return { loadGeoJSON, loadRoads, clearCache };
})();
--------------------------------------------------------------------------------

BEST PRACTICES:
1. Load minimal data at startup (boundaries, config)
2. Load detailed data only when user selects region/layer
3. Cache loaded data to avoid re-downloading
4. Show loading indicators during fetch
